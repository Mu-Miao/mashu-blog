## 让硬件替我收货

阻塞收发我一直用得很踏实，直到要让板子接收"长度不定的命令"。这时的问题已经不是 CPU 累不累，而是**你怎么知道对方说完了一个整体**。

分工是这样的：DMA 只解决"谁来搬"——搬运会儿不用你盯着，字节自己进缓冲区；**IDLE 空闲中断才解决"搬到哪里为止"**：总线连续一个字节时间没有新边沿，硬件就置起 IDLE 标志，等于对方把门铃按完了。

用 Python 的说法类比一下我脑子里的形状：DMA 是我雇了个搬运工，CPU 不用亲自搬、也不用每件都被叫醒（那是中断模式）；缓冲区里有个只读计数器 `CNDTR`，含义是"**还剩多少格没填**"，所以帧长 = 缓冲区总长 − `CNDTR`；IDLE 就是"门外的车长时间没动了 ⇒ 这批货交完了"。

```c
HAL_TIM_Encoder_Start(&htim4, TIM_CHANNEL_ALL);      /* ① CubeMX 不生成，必须手写 */
HAL_UART_Receive_DMA(&huart1, rx_buf, RX_BUF_SIZE);  /* ② 之后每字节由硬件搬 */
__HAL_UART_ENABLE_IT(&huart1, UART_IT_IDLE);         /* ③ 再开"对方说完了"——必须在②之后 */
```

三行的顺序不是风格，是因果。另外接收缓冲区必须是全局变量：**DMA 是硬件在后台写它**，你要是放成函数里的局部数组，函数一返回栈就没了，硬件会往不知道什么地方继续写。

## 症状一：什么都收不到，而且一句错都不报

我配完 DMA 兴冲冲烧进去，中断一次都没进过。检查了半天逻辑，最后是配置层的问题——**NVIC 里 `USART1 global interrupt` 我根本没勾**。

CubeMX 只有在 NVIC 勾了它之后，才会往 `stm32f1xx_it.c` 里生成 `USART1_IRQHandler`；不勾，向量表就落到启动文件里那个 weak 的 `Default_Handler`。最阴的地方是：**你自己手写一个同名函数也不会报错**——编译、链接、烧录全部通过，中断永远不进来。没有任何东西提醒你，因为它不构成任何语法错误。

同理还有一个配置项：DMA 的 Mode **默认是 `Normal`，必须显式改成 `Circular`**。Normal 填满缓冲区就永久停摆，而"IDLE 分帧"整套玩法靠的是它永远绕圈写。这一条在界面上是一个不起眼的下拉框默认值，不是错误提示。

## 症状二：只有第一帧能收到

这是我最想骂人的一次。第一帧好好的，之后再发什么都没反应。三个原因叠在一起，每个都在 HAL 源码的注释之外：

**其一，HAL 不帮你处理 IDLE。**源码里 IDLE 相关的分支全包在 `if (huart->ReceptionType == HAL_UART_RECEPTION_TOIDLE)` 里面，而我用的普通 `HAL_UART_Receive_DMA` 的 `ReceptionType` 是 `STANDARD`。所以 IDLE 标志**要自己判、自己清**——不清会反复进同一个中断，清的动作是"读状态寄存器再读数据寄存器"。

**其二，`HAL_UART_DMAStop()` 会顺手把 IDLE 中断使能关掉。**源码里就是三行干这件事的。而我每处理完一帧都要"停掉 + 重挂"，好让下一帧永远从缓冲区下标 0 开始（省掉跨尾部拼接）。于是重挂之后如果没重新 `__HAL_UART_ENABLE_IT(IDLE)`，症状精确地就是**只有第一帧能收到**。这种"我帮你关了一个你自己打开的开关"的行为，不看源码不可能猜到。

**其三，ORE 溢出标志必须抢在 `HAL_UART_IRQHandler` 之前清。**上一字节还没被 DMA 搬走、新字节又到了，ORE 一置位，紧跟其后的 HAL 处理会判定"接收出了严重问题"，**中止整个 DMA 接收**。不清它，现象也是"能收一次，之后彻底失联"——和其二几乎一模一样。

## 两道缝，和一次自己坑自己

上面那套逻辑贴进中断函数时有个位置要求：读 IDLE、算帧长、拷数据、重挂 DMA 这一整段**必须放在 `HAL_UART_IRQHandler` 之后**（就是那道叫 `USART1_IRQn 1` 的缝）。放前面，HAL 会拿残留的 RXNE/ORE 标志去操作一次你刚挂好的全新接收，行为不可预期。我第一版就贴在了前面，效果是"偶尔对"，那是最难查的一类。

分帧写法有两种，**不能混着用**：一种是每帧处理完 `DMAStop` + 重挂（帧永远从 0 开始，`len = SIZE − CNDTR` 永远成立，代价是重启的几十微秒会漏字节，适合人手动发命令的节奏）；另一种是真环形，自己记下上一帧结束的位置，`len = (head − tail + SIZE) % SIZE`，跨缓冲区尾要拆两段拷贝。

我把这两种混过一次：**用前一种的公式，配后一种的"从下标 0 拷贝"**。结果第一帧永远正确，绕回缓冲区尾部之后拷出来全是垃圾。所以那次之后我加了一条给自己的规矩——**改这类代码前先确认自己用的是哪一种写法，别照抄自己上一次的结论。**

顺便还有一个坑不在中断里：改用 DMA 接收之后，原来那段阻塞回显必须整块删掉。`RxState` 已经被 DMA 占成 `BUSY_RX`，任何阻塞 `HAL_UART_Receive` 只会一直返回 `HAL_BUSY`。同一个串口不要混用两种接收方式。
