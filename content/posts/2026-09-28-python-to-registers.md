## 我的母语是 Python，第二语言才是 C

我是先会 Python 才碰单片机的。所以每次读寄存器手册，脑子里都在跑一个我自己都没意识到的翻译过程：`DR` 是什么？哦，像一个对象的属性。中断是什么？哦，像回调。写的时候不觉得，读代码时那种"要拐一道弯"的损耗非常大。

后来我干脆把这道弯画出来，做成一张表贴在笔记里。它不严谨，但它是我真的能想通的那版本：

| 我会撞见的东西 | 我在 Python 里的对应物 |
|---|---|
| 寄存器（`DR` / `SR` / `CNDTR`） | 对象的公开属性，只不过属性背后是电线：`huart1.Instance->DR = x` ≈ `uart.data_register = x` |
| 外设时钟使能 | 用对象之前得先 import、先建连接；`__HAL_RCC_DMA1_CLK_ENABLE()` 就是"给这台设备通电" |
| 中断（IRQ） | 回调函数：`USART1_IRQHandler` 是"串口出事了自动被叫起来的那个函数" |
| 标志位（RXNE / TXE / ORE / IDLE） | `event.set()` / `event.clear()`；忘了 clear 就会反复触发同一件事 |
| DMA | 一个不需要调度的后台线程：配置一次就一直在那儿搬 |
| Circular（循环模式） | `collections.deque(maxlen=N)` 的环形覆盖行为 |
| ORE（溢出错误） | 生产者快过消费者导致丢包，只是这里的缓冲区只有一格 |
| 阻塞读 + 超时 | 不带 `timeout` 的 `blocking_read()` |
| 小端 float | `struct.pack('<fff', a, b, c)`——把三个字节原样发出去就是一帧数据 |

## 三个最值钱的对应，和它们的失效点

**`volatile` 在 Python 里没有对应物**，因为动态语言根本不做那种优化：编译器不会把变量"缓存进寄存器"就不再回读。而在 C 里，中断和主循环共享的变量少写这三个字母，主循环可能永远看不到旗子被举起来——不是代码错了，是**编译器替你做了一个你不知情的假设**。我第一次撞上时完全没往"变量声明"上想，因为在我的 Python 习惯里，声明从来不是语义的一部分。

**"栈上的缓冲区被硬件写"对应的是"拿着一个已被回收对象的引用"**，而且更严重。`rx_buf` 要是写成函数里的局部数组，函数一返回，那块栈就作废了，而 DMA 是硬件，它不知道栈是什么，会照样往那个地址继续写。Python 里我拿错引用的上限是拿到一个垃圾值；这里上限是把别人的栈帧改花。所以规则变得很朴素：**被硬件后台写的东西，必须是全局或静态的。**

**波特率和帧格式没有 handshake。**Python 里两端谈不拢通常会抛异常，最差也是返回空；串口不，参数不一致时它照收不误，只是收回来全是乱码。**它不告诉你错了，它给你一批错的。**这类"沉默的错误"是我从高层语言转过来最难适应的地方——不是语法难，是**反馈变少了**。

## 这张表的用法

它只用来让我第一遍读懂，不用来证明我理解得对。每个类比都有失效的一刻：寄存器不是属性，它没有类型检查；DMA 不是线程，它不参与调度、也不会有人替你加锁；`deque(maxlen=N)` 不会在写满时给你一个只读的计数器让你算出这一帧多长。

所以我现在的顺序是：**先用 Python 的话把陌生概念拉进已知的形状，再回去把那张表撕掉、按硬件本来的样子读一遍 datasheet。** 表的作用是省掉"这玩意儿是什么"的恐慌，不是省掉后面的功夫。

不过说真的，让我能撑过那段恐慌的，就是"哦，这不就是回调吗"这一句。语言的先期投资是有复利的：它不替你解决新问题，但它决定你面对新问题时的第一反应是"我见过这个形状"，还是"这跟我有关系吗"。

—— 麻薯ta爸
